# Interactive sketch editing (MCAD-P14-004)

Create a new empty global/datum sketch and its source owner with the separate
[P17-002/003 creation commands](sketch-creation.md), then edit it through these
existing forms. Successful unconsumed point-only drafts need no closed profile;
solid consumers still do. Datum admission follows ADR-102; arbitrary custom/face
workplane editing remains separately gated.

Tauri, Agent JSON-RPC and MCP share `modules/desktop/src/sketch_editor.rs`.
The backend owns authored entities, solve/profile diagnostics, DesignPatch,
verification, document history and publication. The SVG canvas owns disposable
local-plane presentation and unit-labelled form drafts only (ADR-058).

| MCP tool / Agent method suffix | Request | Result |
| --- | --- | --- |
| `inspect_sketches` | `path` | `document_id`, `revision`, rows with unchanged `source`, disposable SI `solved`, `workplane_label`, regenerated `resolved_frame`, `constraint_targets`, `suggested_constraint_id` and `curve_edit_targets` |
| `plan_sketch_edit` | `path`, `edit` | Concrete guarded `patch`, solved candidate `state`, verified SI `evidence`; no writes |
| `apply_sketch_edit` | `path`, `edit`, optional opaque `history` | Shared feature tree, opaque history and verified SI evidence |

Agent methods use the `opencad.` prefix. `edit` contains the current `revision`,
exact authored `sketch_id` and a batch of 1–64 typed `operations`, also capped at
64 expanded source operations. Unknown fields refuse. Source IDs remain stable;
clients cannot substitute points generated by stored Rectangle helpers,
projected entities or kernel indices.

Datum-plane edits additionally require exact `edit.document_id` from inspection.
When supplied on global edits it is checked too; legacy global requests may
omit it. A foreign document with identical source revision still refuses datum
edits. A parameter change invalidates reviews; inspect and plan again. Display
frames are never accepted as mutation intent or written over source references.

| `operation` | Fields besides `operation` |
| --- | --- |
| `point` | `id`, `x`, `y`, `create` |
| `line` | New `id`, existing point `start`, `end`, `construction` |
| `rectangle` | New source-ID prefix `id`, opposite corners `x1`, `y1`, `x2`, `y2`, `construction`; creation only, expands to four points/four lines |
| `circle` | `id`, point `center`, `radius`, `construction`, `create` |
| `ellipse` | `id`, point `center`, `major_radius`, `minor_radius`, `axis_angle`, `construction`, `create` |
| `construction` | Authored `id`, `construction` |
| `horizontal`, `vertical` | New constraint `id`, `line` |
| `coincident` | New constraint `id`, point `a`, `b` |
| `distance` | New constraint `id`, point `a`, `b`, length `expr` |
| `radius` | New constraint `id`, circle `target`, length `expr` |
| `remove_constraint` | Existing constraint `id` |

Coordinates and dimensions carry explicit units, for example `0 mm`, `25 mm`
and `30 deg`. Same-kind named parameters use the existing expression resolver.
ADR-108 resolves ordinary point coordinates and circle radii before solving,
including `origin_x + 1 mm` and `diameter / 4 + 5 mm`, while retaining the exact
authored expressions. Invalid/angle units or parameter kinds, unknown names and
non-finite results refuse before solving. Radius/distance must be positive,
coordinates finite within 1e6 SI units, and ellipse admission remains unchanged.
Point replacement preserves its construction flag. Primitive replacements
preserve primitive kind; constraints are added/removed by stable ID.

Only existing authored sketches with exactly one active Sketch feature owner and
global XY/XZ/YZ or admitted source-bound datum workplanes are admitted. The canvas labels the selected plane, SI-derived origin and
local mm scale. Select points/curves by backend-authored IDs; a background click
sets an explicit-unit point draft. Two clicks draft a line with new stable point
IDs; pointer motion displays a construction-style draft overlay. A form can
create/edit a circle or ellipse, mark construction geometry or add/remove the
listed constraints. Review displays the backend-solved candidate, solve state
and verified volume; Apply rechecks the revision and verifies again.

Every admitted sketch is solved, including unconsumed construction geometry.
Underconstrained solutions are permitted and reported; failed/overconstrained
solutions refuse. Unchanged consumer profile bindings must remain valid. Native
publication also verifies assertions and tessellation before atomic file write.
Stale source, unsupported targets, unit, profile, solve and geometry failures
retain source/history and the published scene. Drafts/reviews discard stale
asynchronous replies. Undo/Redo uses existing verified backend history.

## Pointer circle intent (MCAD-P17-004)

Choose Draw circle, click a centre, move to preview and click a radius point.
Coordinates are local mm (rounded to 0.001 mm); radius is the local distance
rounded to six decimal places in mm. The preview is disposable input, not an
authoritative solved shape. Review/apply uses the same two-form batch through
Tauri and typed Agent/MCP:

```json
[
  {"operation":"point","id":"ent:circle_1_center","x":"2.000 mm","y":"-3.000 mm","create":true},
  {"operation":"circle","id":"ent:circle_1","center":"ent:circle_1_center","radius":"5.000000 mm","construction":false,"create":true}
]
```

The UI selects fresh source IDs before review; later collisions refuse without
publishing an orphan centre. One successful apply is one Undo/Redo entry.
Half gestures cannot submit the numeric form. Escape/Discard, tool/sketch/view/
file changes and upstream parameter edits invalidate drafts and late reviews.
Zero radius after coordinate rounding refuses. The backend still checks finite
explicit units, positive radius, source identity/revision, solves, required
assertions and native publication. Construction circles remain construction
geometry; empty parameter graphs resolve unit-bearing circle source without a
dummy parameter or rewriting authored source. Cold and cached regeneration
share this path.

Independent physical fixtures use r=5 mm, depth=6 mm: V=150*pi mm³ and
area=110*pi mm². Analytic Mock primitives and OCCT check absolute bounds and
centroid on XY/YZ/XZ and a tilted datum (3e-7 m bounds/centroid tolerance,
1e-12 m³ volume). Fresh native SI STL grading retains 0.1 mm placement and 1%
volume tolerances, numerical oriented closure at 1 nm and rejects an actual
translated equal-volume mesh. Actual native Linux/Windows event tests are
separate from typed parity; no external host session or new sampler is claimed.

No `.ocad` schema, migration, kernel primitive, sampling policy or dependency is
changed. Native SVG circles/ellipses are presentation only; no polygon replaces
analytic CAD geometry. Arc/stored Rectangle-helper/cubic/NURBS editing, arbitrary/custom/face
workplanes, new sketch/feature creation, trim/offset, constraint replacement,
datum creation/reparenting, assembly editing and cross-process file locking remain outside this form scope.
Required physical nonempty BodyCount still refuses when unavailable.

Evidence: both Mock and OCCT match ellipse volume `pi*40*15*6 mm³`, dimensions
`80×30×6 mm` (3e-7 m bounding-box tolerance accounts for OCCT's 1e-7 m face gaps),
and independently checked solved horizontal/distance constraints. Native file
preview/refusal/Undo/Redo, real MCP stdio parity and actual Linux Tauri WebView
interaction are tested. External host verification remains separate.
See `examples/agent/interactive_sketch_edit.json` and eval `interactive_sketch_edit`.

## Pointer rectangle intent (MCAD-P17-005)

Choose Draw rectangle, click one corner, move to preview and click the opposite
corner. Either direction is accepted in local mm, rounded to 0.001 mm. The
frontend submits one creation-only typed form, for example:

```json
[
  {"operation":"rectangle","id":"ent:rectangle_1","x1":"22.000 mm","y1":"7.000 mm","x2":"2.000 mm","y2":"-3.000 mm","construction":false}
]
```

The shared backend evaluates explicit length expressions, normalizes the
opposite corners and emits eight AddSketchEntity operations: points
ent:rectangle_1_p0..p3, counterclockwise from the initial lower-left corner, then
lines ent:rectangle_1_e0..e3 connecting successive points. These are ordinary
authored Point/Line entities. No Rectangle helper, associative rectangle group,
automatic horizontal/vertical constraints or implied dimensions are stored.
Subsequent point edits can change the shape. Source expressions survive without
dummy parameters; empty and absent parameter graphs regenerate the same solid.

The prefix and all eight derived IDs must be fresh. Derived collisions, even in
the last edge, refuse the entire candidate. Both typed-form count and expanded
source operations are capped at 64; at most eight rectangles fit in one batch.
Construction marks all four edges, leaves points nonconstruction and produces
no closed profile on its own. Tauri and Agent/MCP share review, strict identity/
revision checks, solve/assertion/native verification and atomic history. One
Undo/Redo restores all eight entities. Half gestures cannot submit the numeric
form; Escape/Discard, controls, reload, upstream edits and stale asynchronous
responses invalidate the draft. Zero width/height after rounding refuses.

The independent 20 x 10 x 6 mm prism fixture has V=1200 mm³ and area=760 mm².
Both analytic Mock and OCCT verify XY/YZ/XZ and tilted datum absolute bounds
and centroid (3e-7 m), volume (1e-12 m³) and area (1e-10 m²), with unchanged
authored source across cold/cached regeneration. Packed/expanded round trips
and typed MCP/Agent parity cover atomic publication. Fresh SI STL grading uses
the existing 0.1 mm placement, 1% volume and 1 nm numerical oriented-closure
tolerances; a translated equal-volume mesh fails. Real Linux/Windows pointer
checks are separate from protocol parity and external host verification.
See [the typed example](../../examples/agent/create_pointer_rectangle.json)
and eval create_pointer_rectangle. No persisted schema or new sampler is added.

## Pointer arc intent (MCAD-P17-006)

[ADR-104](../adr/ADR-104-pointer-arc-intent.md) adds one creation-only form to
existing `plan_sketch_edit` / `apply_sketch_edit` commands. Pass current
`document_id`, `revision` and owned `sketch_id`, with one operation:

```json
{"operation":"arc","id":"ent:arc_1","center_x":"2.000 mm","center_y":"-3.000 mm","start_x":"12.000 mm","start_y":"-3.000 mm","end_direction_x":"2.000 mm","end_direction_y":"17.000 mm","clockwise":false,"close_sector":true,"construction":false}
```

All coordinates are explicit local lengths. This creation form accepts constant
unit-bearing expressions; named parameters refuse because deriving ordinary
source does not create an associative helper. Existing parametric Arc source
through DesignPatch remains available under ADR-024. Identity is required even
on global planes. Keep the source-bound datum association and opaque history.

The centre/start click fixes the radius; the third click specifies direction
only. Here it is 20 mm from the centre, while the actual endpoint is (2,7) mm
on the 10 mm circle. Backend computation and ADR-103 admission determine the
source. Refuse zero/full/ambiguous turns, collapsed points, bad units, stale
source/identity, any generated-ID collision or unsupported values. No shortest
arc guess, snapping tolerance, new sampler or spline/NURBS admission is added.

One patch creates `_center`, `_start`, `_end` points and the Arc at `id`.
Centre/start expressions are preserved; endpoint/radius use fixed explicit-mm
strings and angles explicit radians. For `clockwise:true`, the existing CCW
source swaps Arc endpoint references/angles. `_start` remains the first clicked
point. `close_sector:true` adds `_start_ray` from centre to canonical Arc start
and `_end_ray` from Arc end to centre, sharing actual endpoint IDs. Four source
operations for an open arc, six for a sector; the expanded batch cap stays 64.
Construction marks the Arc/radii, with ordinary nonconstruction points.

Open arcs and bounded unconsumed construction drafts can be reviewed without
invented solids. Closed-profile consumers stay strict; assertions and native
verification still gate publication. The returned solved sketch transports
numeric radians for display separately from the original source. One
apply/Undo/Redo covers all additions. Cancel/Escape, branch/closure/view/tool/
sketch/file/upstream changes and late IPC replies cannot restore an old review.
An empty arc tool cannot fall back to an unrelated numeric form.

The [example](../../examples/agent/create_pointer_arc.json) gives a CCW quarter
sector V=150*pi mm³, A=80*pi+120 mm² at depth 6 mm; `clockwise:true` gives the
270° major sector V=450*pi, A=240*pi+120. On +5 mm XY datum the respective
bounds are (2,-3,5)..(12,7,11) and (-8,-13,5)..(12,7,11) mm. Centroids are
(2+d,-3+d,8) and (2-d/3,-3-d/3,8) mm, d=40/(3*pi). Both kernels verify
physical placement/mesh/source/history, including 0° wrap. Native analytic
tolerances remain 1e-12 m³, 1e-10 m² and 3e-7 m; fresh SI STL grading retains
0.1 mm placement, 1% volume and 1 nm oriented closure.

Eval `create_pointer_arc` and `create_pointer_arc_clockwise_major` independently
grade exact source, prior graph/parameters and a fresh native export. Actual
MCP/Agent regression covers both branches on five placements without model
calls. New native Linux/Windows pointer controls have separate acceptance;
MCP expresses typed intent rather than simulating a mouse.

## Pointer ellipse intent (MCAD-P17-007)

[ADR-105](../adr/ADR-105-pointer-ellipse-intent.md) adds creation-only
`ellipse_axes` to the existing sketch planner/applicator. Send current
`document_id`, `revision`, owned `sketch_id` and this operation:

```json
{"operation":"ellipse_axes","id":"ent:ellipse_1","center_x":"2.000 mm","center_y":"-3.000 mm","major_x":"26.000 mm","major_y":"15.000 mm","through_x":"14.000 mm","through_y":"21.000 mm","construction":false}
```

The three clicks mean centre, major-axis endpoint, then a point ON the ellipse.
In major-axis coordinates the third point is (24,12) mm. The backend computes
`a=30 mm`, `b=abs(12)/sqrt(1-(24/30)^2)=20 mm`, with major direction (.8,.6).
Perpendicular projection alone gives 12 mm and creates the wrong ellipse.
The new tool follows this point-on-curve interaction; no implicit axis swap.

All six coordinates are constant explicit local lengths in the editor's finite
absolute 1e6 m bound. Named parameters refuse because this creation form does
not create an associative axis helper. Require finite `1-(x/a)^2 > 1e-9` to
avoid ambiguous inversion near/outside the major span, then reuse ADR-053's
existing `major >= minor > 1 nm`, major at most 1e6 m admission. Bad units,
degenerate axes/third point, foreign/missing identity (including global planes),
stale source/datum and any ID collision refuse the complete edit.

One DesignPatch adds ordinary `id_center` Point and Ellipse `id`, preserving
centre expressions and authored plane/owner. Derived radii are fixed explicit-mm
strings; local angle is explicit radians in [0,2*pi). There are no persistent
axis points, helper, new source tag or schema/migration. Construction marks only
the ellipse. The expanded budget stays 64 additions, hence 32 such intents.
Review is read-only; one apply/Undo/Redo handles both entities. Cancel/Escape,
control/file/upstream changes and late IPC discard incomplete gestures/reviews.
An empty ellipse tool cannot submit unrelated numeric fields. Existing numeric
and raw parametric Ellipse editing remains supported separately.

The [typed example](../../examples/agent/create_pointer_ellipse.json) has profile
area 600*pi mm2 and 6 mm prism volume 3600*pi mm3. On +5 mm XY datum its bounds
are `(2 +/- 12*sqrt(5), -3 +/- 2*sqrt(145), [5,11])` mm and COM (2,-3,8) mm.
Analytic Mock/OCCT mass, area and absolute placed bounds have independent
oracles. Keep ADR-053's 30/20 mm area comparisons: Mock 1e-12 m2, native 5e-9
m2 for existing default surface quadrature; volume 1e-12 m3 and positions 3e-7 m.
Default Mock ellipse tessellation remains explicitly unsupported. Existing whole
native ellipse prisms/copies now use oriented-triangle display normals instead
of legacy +Z placeholders, retaining exact BREP and physical triangle geometry.

Eval `create_pointer_ellipse` checks intended source and a fresh native SI
export, including 0.1 mm bounds/COM/directional supports, 1% volume and 1 nm
oriented closure. Independent major/minor supports detect a sign-reflected
orientation even when volume, COM and world bounds all match. Actual five-case
MCP/Agent parity and new Linux/Windows native interaction are separate evidence;
neither establishes external model-host verification or new sampling admission.

## Selected constraint controls (MCAD-P17-008)

[ADR-106](../adr/ADR-106-selected-sketch-constraints.md) adds a disposable
`constraint_targets` catalogue to each inspection/candidate row: `points`,
`lines`, `circles`, each in authored source order. Points exclude cubic control
points; circles exclude arcs/ellipses. Stored rectangle helpers, projected
geometry and derived IDs are absent. `suggested_constraint_id` is the first
unused `con:control_N` in that sketch. These fields guide clients; every target,
ID, document identity and revision is still rechecked on plan/apply. They are
not persisted in `.ocad` and introduce no schema or mutation operation.

In Select mode, click a line for horizontal/vertical, a circle for radius, or
click a point then Shift-click a distinct second point for distance/coincidence.
The corresponding target lists also support explicit selection. Enter length
with units (or an admitted length parameter), choose Review constraint, inspect
the solved overlay/remaining DOF and verified volume, then Apply. The removal
list uses existing authored constraint IDs. Target/value/control changes,
Escape/Discard, sketch/tool/view/reload/upstream changes invalidate reviews
and late real IPC. Apply shares the existing verified transaction/history path.

`UnderConstrained { dof }` displays its actual remaining DOF; FullyConstrained
displays zero. Refused solves retain the validation class/error prefix and
explain the actual runtime contradiction, redundant count or nonconvergence.
The backend solves admitted copies before resolving dependent datum frames,
so a failed downstream solid cannot hide this diagnosis. No solver rank,
implicit first-point anchor, tolerance, persisted solve state or admission
changes. Existing policy may admit underconstrained states with redundant rows;
these controls do not invent another classification.

Use [the example](../../examples/agent/constrain_selected_circle.json): original
A=(2,-3), B=(26,15) mm, construction guide and radius-5 mm circle remain authored
unchanged. Horizontal, 20 mm point distance and 10 mm radius reduce remaining
DOF 3→2→1→0; solved B=(22,-3) mm. A 6 mm extrusion has volume 600*pi mm³,
surface 320*pi mm² and +5 mm XY datum bounds (-8,-13,5)..(12,7,11) mm, COM
(2,-3,8) mm. Both genuine analytic Mock and OCCT are checked independently,
including alternate/tilted placements. Eval `constrain_selected_circle` requires
the exact intended source, actual backend solved inspection and fresh native
SI output. A direct radius overwrite with the same solid fails source grading.

These controls add/remove constraints. They do not edit a dimension value
in place: removing and reusing an ID inside one patch still refuses. Arc/ellipse
radius, cubic controls and new solver/geometry families remain outside scope.


## Selected construction geometry (MCAD-P17-009)

[ADR-107](../adr/ADR-107-selected-construction-geometry.md) adds disposable
`construction_targets: [{ id, kind, construction }]` to each sketch editor row,
in authored order. Eligible kinds are point, line, circle, ellipse and arc.
Cubic controls/entities, stored rectangle helpers and their derived members,
and projected geometry are excluded. This catalogue is separate from the
circle-only radius constraint catalogue; the backend rechecks eligibility.
No `.ocad` schema, migration or mutation operation changes.

Select a source on the canvas or in Construction geometry. The explicit Review
make construction / Review make ordinary button emits only
`{ "operation": "construction", "id": "ent:disc", "construction": false }`.
The common typed plan produces SetSketchConstruction, preserving all other
source fields, including source units/expressions, references and constraints.
No numeric circle/ellipse replacement is needed to change its flag. Existing
coordinate/dimension expression admission remains unchanged; this feature does
not add arithmetic circle-coordinate/radius expression evaluation.

Every successful plan also returns `profile_effect` with `before` and `after`
closed profiles (`profile_ref`, `entity_ids`), and existing `consumers`
(`feature_id`, `profile_ref`, `suppressed`). These are prepared backend loops,
not frontend-inferred eligibility. Review shows loop counts/membership and the
verified candidate volume or absence of a solid. An ordinary open curve may
form no closed profile. A point construction flag affects that point only;
referencing curves still participate according to their own flags. Removing
or silently rebinding an unchanged consumer's loop refuses atomically.

Review/Apply reuse identity/revision, solve, profile, required assertion,
native tessellation, publication and opaque history guards. Target/sketch/tool/
view/file/upstream changes, Escape/discard and late IPC cancel old results.
The current source catalogue remains in use while candidate geometry previews.
See [the example](../../examples/agent/toggle_selected_construction.json): the
source circle retains `1 cm`, the ellipse retains `15 mm + 15 mm`, and the
final point flag does not remove the consumed circle. Both kernels check
V=600*pi mm³, A=320*pi mm² and independent placed bounds/COM/meshes.
Eval `toggle_selected_construction` grades exact flags/source and fresh native
SI output; a wrong unconsumed ellipse flag fails despite identical solid mass.


ADR-108 also applies strict parameter evaluation to analytic curve-edit/offset
planning and raw source-length patch validation.
`opencad_feature::param_apply::validate_sketch_source_lengths(sketch, scope)`
validates point/radius source without mutation or constraint admission; supply
a strictly evaluated SI scope. `solved_sketch_copy` resolves those lengths on
a clone before solving. The low-level `parse_length_expr` deliberately accepts
only finite simple literals and known length units; arithmetic/parameters belong
to the higher-level evaluator. See
[the source-length example](../../examples/agent/resolve_sketch_source_lengths.json)
and eval `resolve_sketch_source_lengths`. No `.ocad` codec/schema changes.


## Reviewed selected trim and extend (MCAD-P17-010)

ADR-109 adds `curve_edit_targets` to each source row: stored authored line/arc
targets, line/circle/arc cutters and a globally free `suggested_point_id`.
Helpers, derived/projected geometry, cubic controls and ellipses are excluded.
Use `inspect_sketch_curve_edit` (Agent `opencad.inspect_sketch_curve_edit`) with
`path` and `query={document_id,revision,sketch_id,target_id,cutter_id,mode,end}`.
`mode` is `trim|extend`, `end` is `start|end`; identity/revision are required.
It returns unchanged `query`, `new_point_id`, and ordered `intersections` with
`position_m` and target parameter. Discovery is read-only and selects no branch.

Send exactly one operation to the existing plan/apply gateway:

```json
{"operation":"curve_edit","target_id":"ent:guide","cutter_id":"ent:disc",
 "mode":"trim","end":"end","new_point_id":"ent:trim_end_1",
 "intersection_index":1,"remove_constraints":["con:guide_length"]}
```

The explicit index is required even for one intersection. Removals default to
empty, must name unique existing source constraints, and are never inferred.
Expanded operations are capped at 64. Old shared endpoints and source expressions
are retained. The plan includes `curve_edit_effect` with source options, selected
index and actual `solved_position_m`, plus existing profile/consumer/solid effects.
A retained constraint moving the solved endpoint more than 1 nm from the chosen
original intersection refuses. Missing/foreign/stale targets, identity/revision,
ID collisions, invalid branches and consumed-loop loss/rebinding refuse atomically.
Apply rebuilds the plan from current source, checks assertions/display/publication
and preserves opaque Undo/Redo; no `.ocad` schema change.

Native Trim / extend supplies source dropdowns and canvas target/cutter picks,
explicit end/mode/removals, backend intersection dropdowns/keyboard markers,
read-only Review and verified Apply. Control/source/file/view/upstream changes,
Escape/discard and late IPC invalidate old discovery/review.
See [the recipe](../../examples/agent/trim_selected_guide.json) and the runnable
`examples/selected_curve_edit.ocad.d` source before trimming. Its branch 1 is
(10,3) mm; the unchanged cylinder has V=600*pi mm³ and A=320*pi mm².


## Reviewed independent offset copies (P17-011, ADR-110)

`inspect_sketches` rows include backend `offset_targets`: stored ordinary
lines/arcs with stored authored point references (arcs need explicit ends), or
circles. Stored Rectangle helpers/generated edges, projected/cubic/ellipse and
construction curves are excluded. Source must have one active authored owner on
an admitted global/datum workplane. Select a single circle or explicitly ordered
shared-endpoint convex CCW line/arc contour; do not sort/reverse/repair it in UI.
Existing ADR-052 analytic mitre/tangent joins, 256 curves, 1 nm contact/collapse
and finite coordinate limits remain unchanged.

Tauri `plan_sketch_offset_cmd` / `apply_sketch_offset_cmd`, Agent
`opencad.plan_sketch_offset` / `opencad.apply_sketch_offset` and MCP
`plan_sketch_offset` / `apply_sketch_offset` share this transport intent:

```json
{"path":"part.ocad.d","offset":{"document_id":"doc:part","revision":"<inspect_sketches.revision>","source_sketch_id":"sketch:new_1","curve_ids":["ent:offset_disc"],"distance":"3 mm","side":"outward","name":"Independent circle offset"}}
```

`distance` is a positive constant length above 1 nm and at most 1e6 m with
explicit m/mm/cm/in units. `side` is separately `outward` or `inward`.
Unitless/negative/zero/nonfinite/angle/parameter distance refuses. Source
expressions resolve strictly at the current revision. Unknown fields refuse;
clients supply neither output IDs, frames, patches nor an associative mode.

Read-only plan returns `offset`, deterministic globally free
`destination_sketch_id`, `destination_feature_id`, `destination_curve_ids`,
`destination_point_ids`, `signed_distance_m`, `association: independent_copy`,
analytic SI `curves`, solved candidate `state`, whole-document `evidence` and the
revision-guarded DesignPatch. The patch creates the new sketch, literal ordinary
entities and its authored owner atomically; source entities/expressions/flags,
constraints, consumers, parameters and order are retained. The copy uses the
original symbolic workplane; no source constraints are copied. Later source
parameter edits do not update the literal copy, while shared datum edits move
both sketches. There is no persistent curve association.

Review displays actual backend dimensions, new IDs, closed profiles and retained
solid consequences; use `list_features.rows[].closed_profiles` for a subsequent
explicit extrusion. Apply takes the identical current intent plus optional opaque
`history`, recomputes/reverifies the complete candidate including assertions and
native display, re-reads the source before publication and returns
`FeatureEditResult`. Refusal leaves document/history/file/publication unchanged.
Packed/expanded source and canonical Undo/Redo use the existing history gateway.
No .ocad schema changes.

Native controls provide dropdown/canvas/keyboard source picks, an ordered list
with Move up/down/Remove, explicit distance/side/name and separate Review/Create.
Candidate geometry never enters source catalogues. Source/file/tool/view/form,
selection/order/upstream changes, Escape/Discard, another command and late IPC
invalidate the old review. See
[the recipe](../../examples/agent/offset_selected_sketch.json) and the runnable
`examples/selected_offset.ocad.d` original source. Its outward 3 mm circle copy
has radius 13 mm, centre (2,-3) mm; a separate 6 mm copy extrusion has
V=1014*pi mm3, A=494*pi mm2 and datum-plane bounds (-11,-16,5)..(15,10,11) mm.
A rectangle source 80x60 mm becomes 86x66 mm outward or 74x54 mm inward.
